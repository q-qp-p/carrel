# Carrel 0.4.2

[English](0.4.2.md) | 中文

本次更新提供 Light／Standard 两种部署版本，将应用和调度器容器化，并将模型配置与模型服务部署解耦。解析、图谱抽取和检索算法延续 0.4.1。

## 部署与存储

- **Standard** 通过统一存储接口使用 Qdrant、OpenSearch 和 Neo4j。
- **Light** 使用内嵌 LanceDB、DuckDB 提供向量、关键词和图谱访问，包含原文回读、时序事实、图谱版本和维护回收。两个版本均使用 SQLite 管理应用状态。
- 两个版本共用应用镜像，在容器内运行控制台、检索 API 和持久化后台调度器。MinerU 保留为独立的集成解析容器，宿主机需要 Docker 与 Compose v2。
- `deploy.sh` 调整为可选的 Compose 辅助入口。定时任务由应用容器调度，队列持久化，重启后恢复任务。
- 部署时选择版本，每个数据目录保持该选择。

## 模型配置与控制台

- **系统设置** 分为 LLM、Embedding 和 Reranker，独立配置接口地址、模型 ID 和密钥。Carrel 不部署这些模型服务或下载其权重；MinerU 仍下载自身解析资源。
- 保存配置时自动验证接口。文本向量返回维度须与配置一致，视觉接口使用合成图片验证；验证失败保留已保存配置。
- 向量模型支持批量大小和请求并发配置；LLM 增加多模态标记及并发上限，供图片描述和建图任务使用。
- 解析与建图统一开始、暂停、继续的按钮逻辑，调整模型卡片、密钥显隐及中英文文案。Light 不展示「系统服务」，容器启停通过 Compose 管理。

## 部署或升级

```bash
git clone https://github.com/FengZhenfei/carrel.git
cd carrel
./deploy.sh --standard --build
# 或：./deploy.sh --light --build
```

打开 `http://127.0.0.1:9800` 配置模型接口，将文件夹放入 `data/runtime/mirror/`。使用 NVIDIA Container Toolkit 时可加 `--gpu` 启用 GPU 解析。

已有 Standard 安装应保留配置、原文件、状态数据库、索引、图谱和解析缓存，并映射到新部署。启动容器调度器前先停止旧调度器，保留的资产可直接复用，无需重新解析或建图。模型地址需从应用容器内可达，`127.0.0.1` 指向容器自身；迁移后通过 Compose 管理应用。
