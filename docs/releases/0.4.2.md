# Carrel 0.4.2

English | [中文](0.4.2.zh-CN.md)

This release adds Light and Standard deployment editions, packages the application
and scheduler in a container, and separates model configuration from service deployment.
The parsing, graph extraction and retrieval algorithms continue from 0.4.1.

## Deployment and storage

- **Standard** uses Qdrant, OpenSearch and Neo4j through a shared storage interface.
- **Light** uses embedded LanceDB and DuckDB for vector, keyword and graph access,
  including source readback, time-scoped facts, graph versions and maintenance.
  SQLite tracks application state in both editions.
- Both editions use the same application image. It runs the console, search API
  and a persistent background scheduler. MinerU remains an integrated, separate
  parser container. The host needs Docker with Compose v2.
- `deploy.sh` is now an optional Compose helper. Scheduled work runs inside the
  application container, with persistent queues and restart recovery.
- Choose the edition when deploying. Each data directory keeps that choice.

## Model configuration and console

- **System settings** has separate LLM, Embedding and Reranker sections. Configure
  endpoints, model IDs and keys independently; Carrel does not deploy these model
  servers or download their weights. MinerU still downloads its own parser assets.
- Saving a model configuration checks its endpoint. Text embeddings must return
  the configured dimensions; visual checks send synthetic images. Failed checks
  preserve the saved configuration.
- Embedding batch size and request concurrency are configurable. LLM settings add
  a multimodal flag and a concurrency limit used by image descriptions and graph jobs.
- Parsing and graph controls share start, pause and resume behavior. Model cards,
  key visibility and bilingual labels are aligned. Light omits System services;
  container lifecycle is managed through Compose.

## Deploy or upgrade

```bash
git clone https://github.com/FengZhenfei/carrel.git
cd carrel
./deploy.sh --standard --build
# Or: ./deploy.sh --light --build
```

Open `http://127.0.0.1:9800`, configure model endpoints, and add document folders
under `data/runtime/mirror/`. Use `--gpu` for GPU parsing with NVIDIA Container Toolkit.

For an existing Standard installation, retain its configuration, source documents,
state database, indexes, graphs and parser caches, and map them into the new
deployment. Stop the old scheduler before starting the container scheduler.
The retained assets can be reused without reparsing or rebuilding graphs. Model
URLs must be reachable from the application container; `127.0.0.1` refers to that
container. After migration, manage the application with Compose.
