# 存储适配接口

[English](storage.md)

Standard 和 Light 共用统一存储入口。解析任务、本体标签采样、建图、
检索服务和控制台切块预览通过 `kb_pipeline.storage.get_storage()` 访问存储。

## 接口职责

| 接口 | 职责 | Standard | Light |
|---|---|---|---|
| `ChunkStore` | 集合维度、向量读写、切块与上下文读取、旧版本失活、元数据更新与恢复 | Qdrant | LanceDB |
| `KeywordStore` | 文档索引同步、关键词候选、短语查询、选库所需词法信息 | OpenSearch | LanceDB 全文检索 |
| `GraphStore` | 建图输入、版本化向量与图谱写入、发布与回滚、图谱查询、事实、日期和原文回读 | Qdrant 与 Neo4j | LanceDB 与 DuckDB |
| `Storage` | 组装各接口、知识库目录、单次请求截止时间 | Standard 适配工厂 | Light 适配工厂 |

SQLite 继续管理配置、任务队列、切块台账与建图记录。原文件和解析资产沿用现有路径。

Standard 适配器调用原有存储实现。解析、切块、实体抽取、模式演进、排序和证据组装
沿用原算法。来源标识、文档版本、图谱版本、时间范围和原文定位信息原样传递。

Standard 版本发布顺序保持为：写入新向量、导入图谱、切换向量别名、激活图谱版本、记录成功。
激活失败时恢复原别名。关键词索引失败后仍单独排队补偿。检索读取有效切块；
重新解析发布期间，控制台预览可以读取台账仍指向的上一版本。

连接按需建立，同一适配器的并发调用共享向量客户端。检索配置刷新时，接口地址、
密钥和超时未变化则复用连接；执行中的请求保留自己的配置。请求截止时间和各通道
故障降级行为保持原样。

## 验证

在仓库根目录运行本地回归：

```sh
app/.venv/bin/python -m pytest -q app/tests
```

`test_storage_contract.py` 使用通用合成的 Markdown、代码示例、普通文本和 CSV，
运行真实解析器、SQLite 和内存 Qdrant，检查内容保留、来源标识、向量与过滤结果一致性、
建图输入、覆盖入库及空文档撤回。模型响应和 OpenSearch 通信使用可控夹具。
既有回归还覆盖增量建图、删除与改名、发布回滚、断点恢复、时序和冲突查询、图片引用及
接口配置刷新。

`test_storage_live.py` 使用真实 Qdrant、OpenSearch 和 Neo4j 验证同一文件生命周期，
并构建两个图谱版本、回读来源、注入激活失败，检查回滚及重试。模型响应仍使用合成夹具，
以便重复验证存储行为。

这组测试需要**专用、可销毁的数据库**：回环端口 16333 为 Qdrant，19200 为 OpenSearch，
17687 为关闭认证的 Neo4j。测试先确认 Qdrant 和 Neo4j 为空，每项结束后清除测试集合及
图谱节点。不要将这些端口映射到现有数据库。

```sh
CARREL_STORAGE_INTEGRATION=1 app/.venv/bin/python -m pytest -q app/tests/test_storage_live.py
```

## Light 存储

`light_data.py` 使用 LanceDB 原生实现切块存储、精确余弦向量检索和关键词候选。
原始属性、向量和关键词字段保存在同一行，缺失的视觉向量保留为空。支持来源过滤、
上下文读取、文件覆盖、元数据更新、恢复及原文短语查找。关键词评分累加不同字段的贡献，
并为文件名和路径建立子串索引。其 BM25 排名可以与 OpenSearch 不同，因此分别核对
向量、关键词和合并候选的结果。

`light_graph.py` 将各版本的节点和边保存到不可变的 LanceDB 表，通过 SQLite 原子切换
完整版本的指针。查询固定读取开始时选定的版本，重试可复用中断写入留下的表。已暂存或
发布的版本号不能换成另一份图谱内容。DuckDB 在进程内执行证据关联查询，限制内存和
临时磁盘用量；来源日期、冲突和治理沿用现有公共筛选规则。

安装可选依赖后运行原生存储回归：

```sh
app/.venv/bin/python -m pip install -e './app[light]'
app/.venv/bin/python -m pytest -q app/tests/test_light_data.py app/tests/test_light_graph.py app/tests/test_light_integration.py app/tests/test_light_lifecycle.py
```

测试覆盖通用合成文本、代码和表格、文本与视觉过滤、关键词更新、并发写入、来源证据、
时序与冲突、历史版本不可变、查询版本固定以及图谱暂存期间的进程退出。安装可选依赖时，
真实服务联调还会对比两个图谱版本与 Neo4j 的节点属性、证据路径。

## 查询与维护

Light 提供与 Standard 相同的实体列表、一跳邻域、事实、冲突、时间序列、编译页及
原文回读接口。排序、时间口径和证据格式继续使用公共实现，实体别名、归并前的 ID、
文档版本和失效引用校验保持原有语义。Light 默认采用精确向量检索。

图谱向量与结构投影先完成暂存，再通过一个 SQLite 指针同时发布。发布时锁定该版本，
后续不能改写其向量。准备失败时，上一版本继续可用；回滚也切换同一指针。
查询固定读取选定的版本；回收等待正在读取的查询结束，保护当前版本与可恢复任务，
并执行版本保留数量和保留期限规则。中断遗留的图谱表与向量在保留期后回收。
失活切块和解析资产清理已接入原生存储读取。
每周维护还会整理切块表、回收 Lance 旧文件，为近期内部快照和未确认的写入保留 7 天安全窗口；
这个存储窗口与图谱历史版本保留策略分别生效。

Light 集成测试在临时 LanceDB／DuckDB 数据上运行真实解析器、任务队列、建图、发布、
HTTP 检索及图谱接口，外部模型响应使用确定性夹具。回归还覆盖过期与有效数据、
回收预演、回滚、发布中断、失效引用、查询时限、时序与冲突分页及来源证据。

## 部署

在新的部署目录选择版本：

```sh
./deploy.sh --standard --build  # Qdrant、OpenSearch、Neo4j 容器
./deploy.sh --light --build     # 内嵌 LanceDB 与进程内 DuckDB
```

两个版本都集成 MinerU，共用包含两种存储适配器的应用镜像，并在
`data/runtime/deployment-mode` 和 `KB_STORAGE_BACKEND` 中记录版本。重复运行保持原选择；
另一版本使用独立部署目录，不提供控制台切换或跨模式迁移。
Light 数据默认位于 `data/runtime/storage`，可通过 `KB_STORAGE_ROOT` 指定其他路径；
控制台不展示「系统服务」。原生存储检查执行实际读取，不以目录或软件包存在作为健康判断。

向量、重排及文本／多模态模型均独立配置接口，两个版本都不启动这些模型容器或下载其权重。
MinerU 自身的解析权重仍在首次启动时下载。
